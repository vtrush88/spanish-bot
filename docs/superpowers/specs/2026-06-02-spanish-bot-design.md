# Telegram-бот: персональный тренажёр испанского для мамы

**Дата:** 2026-06-02
**Статус:** дизайн утверждён, готов к плану реализации

## Что строим

Телеграм-бот — **персональный тренажёр испанского для мамы** (учит с нуля, весь интерфейс на русском).

Мама сама добавляет слова или целые фразы, которые ей нужно выучить. Бот через LLM
дополняет каждую запись переводом, произношением (аудио + русская транскрипция) и
примером-предложением. Затем тренирует тремя способами: карточки с интервальным
повторением, проверка перевода, аудирование.

**Режим взаимодействия:** pull — мама заходит когда хочет и жмёт кнопку. Пуш-уведомлений
и планировщика в MVP нет.

**Пользователи:** одна мама (и Victoria для теста). Данные ключуются по `user_id`, чтобы
позже можно было добавить других людей без переделки схемы.

## Выбранный подход (Вариант A)

- **Стек:** Python + `aiogram`.
- **Хранилище:** SQLite (один файл, без отдельного БД-сервера).
- **Telegram:** long-polling — не нужен публичный HTTPS-адрес, webhook'и, сертификаты.
- **LLM:** Claude API (Anthropic) — обогащение слов, проверка перевода, генерация
  русской транскрипции. Структурированный вывод через tool use (форсированная JSON-схема).
- **TTS:** бесплатный `edge-tts` (голоса Microsoft, испанский) с запасным вариантом `gTTS`.
- **Хостинг:** управляемый дешёвый хост (Railway / Fly.io) — всегда онлайн,
  авто-перезапуск при падении, деплой в пару команд. ~0–5 $/мес.

Отклонённые альтернативы: webhook + serverless (оверкилл для одного пользователя,
холодные старты, нужен HTTPS); локальный хостинг дома (машина должна быть всегда
включена — хрупко для ежедневного использования).

## Архитектура и компоненты

Один Python-процесс (`aiogram`, long-polling), рядом файл SQLite.

```
spanish-bot/
├── bot.py            # точка входа: запуск, роутинг, регистрация хендлеров
├── config.py         # чтение env: TELEGRAM_TOKEN, ANTHROPIC_API_KEY, ALLOWED_USER_IDS
├── handlers/
│   ├── menu.py       # /start, главное меню (большие кнопки внизу)
│   ├── add.py        # добавление слова/фразы
│   └── training.py   # три режима тренировки
├── services/
│   ├── enrichment.py # Claude API: вход (слово/фраза) → перевод, транскрипция, пример
│   ├── grading.py    # Claude API: проверка маминого перевода (прощает опечатки)
│   ├── tts.py        # edge-tts: испанский текст → голосовое (ogg)
│   └── srs.py        # логика интервального повторения (когда показывать снова)
├── db.py             # SQLite: CRUD карточек + расписание повторений
└── tests/
```

### Границы ответственности

| Модуль | Что делает | От чего зависит |
|---|---|---|
| `handlers/*` | только разговор с Telegram (кнопки, приём текста) | вызывают services + db |
| `services/enrichment`, `grading` | общение с Claude, возвращают чистые данные (dict) | Anthropic SDK |
| `services/tts` | текст → аудиофайл | edge-tts |
| `services/srs` | чистая функция: «карточка + оценка → когда следующий показ» | ничего (легко тестить) |
| `db` | хранение и выборка карточек «к повторению» | SQLite |

**Ключевые принципы:**
- Хендлеры тонкие — вся логика в services/db, которые тестируются без Telegram.
- `srs` — чистая логика без побочных эффектов; покрывается тестами в первую очередь.
- Доступ: бот отвечает только пользователям из `ALLOWED_USER_IDS`, на чужих не реагирует.

## Модель данных

**Таблица `cards`** (одна строка = одно слово или фраза):

| Поле | Что хранит |
|---|---|
| `id` | первичный ключ |
| `user_id` | чей это словарь |
| `kind` | `word` или `phrase` |
| `spanish` | испанский текст |
| `russian` | перевод |
| `transcription` | русскими буквами, напр. `о́ла` |
| `example_es` | пример-предложение на испанском |
| `example_ru` | перевод примера |
| `audio_file_id` | Telegram `file_id` озвучки (кэш) |
| `enriched` | флаг: дополнена ли карточка через LLM |
| `created_at` | дата добавления |
| `due_at` | когда показать снова |
| `interval_days` | текущий интервал |
| `reps` | сколько раз повторяли |
| `lapses` | сколько раз забывала |

Опционально позже: таблица `review_log` для статистики. В MVP не нужна.

### Интервальное повторение (Leitner-лесенка)

- После карточки мама жмёт одну из двух кнопок: **«Помню» / «Не помню»**
  (двух градаций достаточно для новичка).
- «Помню» → интервал растёт по лесенке: `1 → 3 → 7 → 14 → 30 → 60` дней.
- «Не помню» → сброс на начало (1 день), `lapses += 1`.
- `due_at = сегодня + interval_days`. На тренировку берутся карточки с `due_at <= сегодня`
  плюс новые (ещё не повторявшиеся).
- Реализация: две чистые функции — `srs.next_interval(current: int, remembered: bool) → int`
  (лесенка) и `srs.due_on(today: date, interval_days: int) → date`.

### Кэш аудио

При первой отправке голосового Telegram возвращает `file_id`. Сохраняем его и при
следующих показах шлём по `file_id` — не перегенерируем TTS каждый раз (быстрее,
бесплатно). Если `audio_file_id` пуст — генерируем через edge-tts, отправляем,
запоминаем `file_id`.

## Сценарии и UX

Принцип для мамы-новичка: **постоянные большие кнопки внизу экрана**, никаких команд
для запоминания, всё по-русски и дружелюбно.

**Главное меню** (reply-клавиатура, всегда видна):
```
[ ➕ Добавить слово ]
[ 🎴 Карточки ]  [ ✍️ Проверить себя ]
[ 🎧 Аудирование ]  [ 📖 Мой словарь ]
```

### 1. Добавление слова/фразы
```
Мама: comida
Бот:  🔤 comida
      🇷🇺 еда
      🗣 произношение: комИда   [+ 🔊 голосовое]
      📝 пример: La comida está lista. — Еда готова.
      Сохранить? [ ✅ Да ]  [ ❌ Нет ]
```
Бот определяет язык ввода (испанский/русский) и обогащает через Claude.
Работает и для одного слова, и для целой фразы. (Кнопка «Исправить перевод»
была в первой версии и удалена 2026-06-10 как лишняя.)

### 2. Карточки (берём `due_at <= сегодня` + новые)
```
Бот:  🎴 comida   [🔊]
      ...вспомни перевод...
      [ 👁 Показать ответ ]
(после нажатия)
Бот:  🇷🇺 еда  ·  комИда
      [ ✅ Помню ]  [ 🔁 Не помню ]
→ следующая карточка, пока есть «к повторению»
```

### 3. Проверить себя (перевод)
```
Бот:  Как по-испански: «еда»?
Мама: komida   (с опечаткой)
Бот:  ✅ Верно! (komida → comida, маленькая опечатка)
      [следующее слово]
```
Claude оценивает: верно / почти (опечатка) / неверно — мягко, с правильным написанием.
Результат двигает SRS так же, как кнопка «Помню/Не помню».

### 4. Аудирование
```
Бот:  🔊 [голосовое]  Что это за слово?
Мама: comida
Бот:  ✅ Да! 🔤 comida — еда
```

### 5. Мой словарь
Компактный список (5 слов на страницу) + карточка слова по тапу.
```
Бот:  📖 Твой словарь (стр. 1/3, 12 слов)

      1. llave — ключ
      ...
      5. agua — вода
      [ 1 ][ 2 ][ 3 ][ 4 ][ 5 ]
      [ ◀ ]  [ ▶ ]
(тап по номеру — сообщение редактируется в карточку + голосовое)
Бот:  🔤 zumo
      🇷🇺 сок
      🗣 произношение: сУмо
      📝 пример: Bebo zumo. — Я пью сок.
      [ 🗑 Удалить ]  [ ◀ К списку ]
```
Удаление — только внутри карточки; после удаления и «К списку» возврат на ту же
страницу (с поправкой, если страница исчезла). В callback'ах ездит стабильный
`card_id` + номер страницы, а не порядковый номер.

**Пустое состояние:** если карточек «к повторению» нет — «На сегодня всё повторили! 🎉
Можешь добавить новые слова или повторить всё подряд».

## Обработка ошибок

- **Claude недоступен / ошибка обогащения** → ввод не сохраняется (чтобы не плодить
  «пустые» карточки): «Не получилось обработать сейчас 😕 Попробуй ещё раз через минутку».
  Мама остаётся в режиме ввода, следующее сообщение повторяет попытку. (Сохранение «как
  есть» с `enriched=false` и фоновое дообогащение — вынесено вне MVP, см. ниже.)
- **TTS упал** → карточка сохраняется с текстом и транскрипцией, без голосового
  («озвучка временно недоступна»).
- **Не-текстовый ввод** (картинка/стикер/голос) → «Я понимаю пока только текст 🙂
  Напиши слово или фразу».
- **Кривой/неполный ответ Claude** → структурированный вывод через tool use; на
  несоответствие — один повтор, затем graceful-сообщение.
- **Чужой пользователь** → молча игнорируем (только `ALLOWED_USER_IDS`).
- **Падение процесса** → управляемый хост перезапускает автоматически; aiogram
  переподключается к Telegram сам.

## Тестирование (по слоям, снизу вверх)

| Что тестируем | Как |
|---|---|
| `srs.next_state` — лесенка интервалов | юнит-тесты на чистой функции (рост, сброс, границы) — пишем первыми, TDD |
| `db` — CRUD и выборка «к повторению» | тесты против временной/in-memory SQLite |
| `enrichment` / `grading` | мок ответа Claude; проверка парсинга и обработки кривого ответа |
| `tts` | на входной текст создаётся непустой аудиофайл (или мок) |
| хендлеры | держим тонкими; тестируем сервис-функции под ними; точечно aiogram-тест-утилиты |

Принцип: вся значимая логика живёт в `services`/`db`/`srs` и тестируется **без живого
Telegram и без реальных вызовов API**.

## Открытые вопросы / на будущее (вне MVP)

- Пуш-напоминания раз в день (нужен планировщик).
- Статистика прогресса (`review_log`).
- Несколько пользователей (схема уже готова через `user_id`).
- Распознавание речи мамы (она произносит — бот проверяет).
