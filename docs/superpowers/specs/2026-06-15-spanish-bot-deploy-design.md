# Spanish Bot — Deploy to VPS, Design

**Дата:** 2026-06-15
**Статус:** дизайн утверждён, ждёт плана реализации
**Связано:** основная спека `2026-06-02-spanish-bot-design.md`; операционка — `AGENTS.md`

## Цель

Перевести бота с «запускается только внутри сессии Claude Code на маке Victoria» на
постоянный always-on хостинг на собственном VPS (DigitalOcean), чтобы мама могла
пользоваться ботом в любой момент, независимо от того, включён ли мак.

## Чего НЕ делаем (YAGNI)

- ffmpeg — не нужен (озвучка идёт как mp3 в `sendVoice`).
- Docker, Postgres, nginx/веб-сервер, домен, HTTPS — ничего из этого: бот на
  long-polling сам ходит к Telegram, входящих портов нет.
- Off-site / облачные бэкапы, снапшоты дроплета — осознанно отложено (см. «Бэкап»).
- CI/CD, авто-деплой по push — обновление ручное (одна команда), этого достаточно.

## Архитектура

Один Python-процесс (`bot.py`, long-polling) на маленьком VPS под управлением systemd.
SQLite-файл и `.env` живут на диске сервера. Код приезжает через `git pull` из приватного
GitHub-репозитория. Схема не меняется — это тот же бот, что и локально, просто с другим
способом запуска и хранения.

```
[мак: git push] --> [приватный GitHub repo] --> [VPS: git pull]
                                                     |
                          systemd (spanish-bot.service, Restart=always)
                                                     |
                                              python bot.py  --long-polling-->  Telegram
                                                     |
                                       spanish_bot.db (SQLite, на диске VPS)
                                                     |
                                  cron: ночная копия в backups/ (хранить 7)
```

## Компоненты и решения

### 1. Сервер
- DigitalOcean Basic Droplet, минимальный тариф (~$4–6/мес, 512 МБ–1 ГБ RAM —
  с запасом для одного бота и пары пользователей).
- Ubuntu 24.04 LTS. Регион поближе к пользователям (Frankfurt / Amsterdam) — для
  удобства SSH; на long-polling латентность не влияет.
- Установить: `python3.12`, `python3.12-venv`, `git`. Больше ничего.
- Доступ по SSH-ключу (не паролю). Базовый firewall (`ufw`): впускать только SSH.

### 2. Код — приватный GitHub-репозиторий
- Завести **приватный** репозиторий (напр. `victoriatrush/spanish-bot`), добавить как
  remote к существующему локальному репо `app/`, запушить `main`.
- На сервере: `git clone` → `python3.12 -m venv .venv` →
  `.venv/bin/pip install -r requirements.txt`.
- `.gitignore` уже исключает `.env`, `*.db`, `.venv` — секреты и данные в git не попадают.

### 3. Секреты и стартовые данные — один раз по `scp`
- `.env` скопировать с мака на сервер (тот же `TELEGRAM_TOKEN`, `ANTHROPIC_API_KEY`,
  `ALLOWED_USER_IDS`). Права `chmod 600 .env`.
- Текущий `spanish_bot.db` скопировать с мака на сервер — чтобы переехали уже
  добавленные мамой слова и расписание SRS. (Сделать при остановленном локальном боте,
  чтобы файл не писался в момент копирования.)

### 4. Запуск — systemd
- Юнит `spanish-bot.service`:
  - `WorkingDirectory=` папка репо; `ExecStart=<repo>/.venv/bin/python bot.py`;
  - `Restart=always`, `RestartSec=5` — переживает краш;
  - `WantedBy=multi-user.target` + `systemctl enable` — поднимается после ребута;
  - запуск от непривилегированного пользователя (не root).
- Логи: `journalctl -u spanish-bot -f`. Отдельный файл логов не нужен.

### 5. Бэкап БД
- cron раз в сутки: копировать `spanish_bot.db` в `backups/spanish_bot-YYYY-MM-DD.db`.
- Хранить 7 последних, старые удалять (ротация в том же скрипте).
- Локально на дроплете. **Известное ограничение:** защищает от порчи/случайного
  удаления данных, но НЕ от гибели самого дроплета. Off-site — будущее улучшение,
  осознанно вне этого этапа.

### 6. Рутина обновлений (после деплоя)
```bash
# на маке
git push
# на сервере (ssh)
cd <repo> && git pull
.venv/bin/pip install -r requirements.txt   # только если менялся requirements.txt
sudo systemctl restart spanish-bot
journalctl -u spanish-bot -n 20             # убедиться: Start polling, нет ошибок
```

## Критический момент перехода — один поллер на токен

У одного бот-токена может быть только ОДИН активный long-polling процесс, иначе
`TelegramConflictError`. Поэтому при переходе на сервер **локальный бот на маке
гасится навсегда** (`pkill -f "MacOS/Python bot.py"`), и «боевая» версия с этого
момента живёт только на VPS. Локально мак остаётся для разработки — но запускать
там бота с тем же токеном, пока работает серверный, нельзя. (Для локальной отладки
без конфликта — отдельный тестовый токен от @BotFather.)

## Обработка ошибок и крайние случаи

- **Краш процесса** → systemd перезапускает (`Restart=always`).
- **Ребут сервера** → сервис стартует сам (`enable` + `multi-user.target`).
- **Ошибка при старте** (битый `.env`, нет зависимости) → сервис падает в цикле
  рестарта; диагностика через `journalctl`. Ран-бук это описывает.
- **Перенос БД при включённом локальном боте** → риск копирования на середине записи;
  митигируется тем, что локального бота останавливаем ПЕРЕД `scp`.

## Тестирование / проверка

Деплой — инфраструктурный, юнит-тестами не покрывается. Проверка — по ран-буку:
1. `systemctl status spanish-bot` → `active (running)`.
2. `journalctl` → `Start polling`, нет `TelegramConflictError`.
3. Живой тест в Telegram: `/start`, добавить слово, тренировка, аудио-произношение.
4. Ребут сервера → бот сам поднялся.
5. Прогнать скрипт бэкапа вручную → файл появился в `backups/`.
